# 当前布局与交互存在的问题

> 发现日期：2026-09-15
> 发现方式：构建 M1 产物后，在本地 HTTP 服务器中以 320px / 360px / 400px / 500px 四种宽度、浅色/深色双模式实际走查所有视图（对话 / 设置·API配置 / 设置·角色 / 设置·偏好 / 会话列表）。
> 严重程度：🔴 严重（影响核心可用性） · 🟡 一般（影响美观或体验） · 🟢 轻微（细节优化）

---

## 一、布局问题（Layout）

### L-01 🔴 会话列表展开时主内容区被严重挤压

**现象**：在 320px 宽度（Chrome 侧边栏默认最小宽度附近）下，左侧导航栏 `w-16`（64px）+ 会话列表 `w-60`（240px）= 304px，主内容区仅剩约 16px，完全不可见、不可用。

**复现**：
1. 打开侧边栏，宽度设为 320px
2. 点击左侧导航栏顶部的"会话列表"图标
3. 对话视图被挤压到几乎看不见

**根因**：`App.tsx` 中会话列表与主内容区为**并排 flex 布局**，会话列表固定 240px 宽度，不随容器宽度自适应。

**影响范围**：所有使用会话列表的场景；320–360px 宽度下尤其严重。

---

### L-02 🔴 角色列表中角色名称竖排显示

**现象**：在角色列表（设置 → 角色）中，角色名称区域宽度不足，导致中文名称被强制换行成竖排：
- "翻译官" → "翻 / 译 / 官"（三行竖排）
- "摘要助手" → "摘 / 要 / 助 / 手"（四行竖排）
- "在伴 Atmate" → "在伴 / Atmate"（两行）

同时，"默认"标签与角色名称重叠，操作按钮（复制 / 编辑 / 删除）与名称挤在同一行。

**复现**：
1. 设置 → 角色 tab
2. 查看任意角色卡片

**根因**：`RoleList.tsx` 中角色卡片使用 `flex items-start justify-between`，左侧名称区 `min-w-0 flex-1`，右侧操作按钮区 `shrink-0`，但名称区没有 `whitespace-nowrap` 或最小宽度保护，且操作按钮占据了过多水平空间。

**影响范围**：角色列表视图；所有宽度下均存在，320px 最严重。

---

### L-03 🟡 左侧导航栏与主内容区颜色不一致

**现象**：左侧导航栏（`Sidebar.tsx`）使用 `bg-surface`，但在浅色模式下实际渲染为深色背景（与主内容区 `#f6f6f4` 形成强烈对比）。检查代码发现 `Sidebar.tsx` 的 `aside` 元素写的是 `bg-surface`，但实际渲染效果偏暗——可能是 Tailwind v4 `@theme inline` 映射或 CSS 层叠问题。

**复现**：
1. 浅色模式下打开任意视图
2. 观察左侧 64px 导航栏与主内容区的颜色差异

**根因**：待排查——`style.css` 中 `--surface: #ffffff`（浅色），`Sidebar.tsx` 使用 `bg-surface`，理论上应为白色。实际渲染为深色，可能是：(a) 某个全局样式覆盖了 background；(b) Tailwind v4 语义色映射顺序问题；(c) 浏览器扩展页面的默认背景色干扰。

**影响范围**：所有视图；浅色模式下视觉不统一。

---

### L-04 🟡 API 配置表单中"映射方式"下拉框文字截断

**现象**：在 API 配置新建/编辑表单中，思维强度区域的"映射方式"下拉框（`<select>`）选项文字过长，在 320px 宽度下被截断：
- "reasoning_effort（DeepSeek / OpenAI o 系列）" → 显示为 "reasoning_effort（DeepS..."

**复现**：
1. 设置 → API 配置 → 新建配置
2. 向下滚动到"思维强度"区域
3. 查看"映射方式"下拉框

**根因**：`ApiConfigForm.tsx` 中 `<select>` 使用 `className="input"`，没有设置文本溢出处理，且选项文字本身较长。

**影响范围**：API 配置表单；320–360px 宽度下明显。

---

### L-05 🟡 输入框禁用提示重复

**现象**：当未配置 API 时，Composer 区域出现两处重复提示：
1. 输入框上方：`请先在设置中添加并激活 API 配置`（`disabledReason`）
2. 输入框 placeholder：`请先配置 API 并选择角色`

两处文字意思相同但措辞不一致，且同时出现在视觉上很近的位置，显得冗余。

**复现**：
1. 不配置任何 API（或删除所有配置）
2. 查看对话视图底部的 Composer 区域

**根因**：`ChatView.tsx` 计算 `disabledReason` 并传给 `Composer`，`Composer` 又在 placeholder 中硬编码了类似提示。

**影响范围**：对话视图；未配置 API 时始终出现。

---

### L-06 🟡 对话视图空状态缺少配置引导

**现象**：对话视图空状态（无消息时）仅显示：
- "开始一段对话"
- "输入消息或从网页划词发送"

但对于首次使用、尚未配置 API 的用户，这个空状态没有引导他们去设置中配置 API。用户看到空状态后往下看才发现输入框被禁用，增加了认知负担。

**复现**：
1. 新建会话或清除所有消息
2. 查看对话视图中央的空状态

**根因**：`MessageList.tsx` 空状态是硬编码的通用提示，没有根据"是否已配置 API"动态显示引导。

**影响范围**：对话视图；首次使用体验。

---

### L-07 🟡 Token 状态条进度条过细、信息密度低

**现象**：
- 进度条高度 `h-1.5`（6px），在侧边栏中不易观察
- 状态条占据完整一行显示 `≈0 / 128,000 tokens` 和 `累计 ≈0`，信息密度低
- 当 token 数为 0 时，进度条不可见（0% 宽度），用户可能意识不到这里有个进度条

**复现**：
1. 查看对话视图底部、Composer 上方的 TokenStatusBar

**根因**：`TokenStatusBar.tsx` 设计为独立一行，进度条高度固定 6px。

**影响范围**：对话视图；始终可见。

---

### L-08 🟢 设置视图 Tab 栏只有文字无图标

**现象**：设置视图顶部的 Tab 栏（API 配置 / 角色 / 偏好）只有文字标签，没有图标辅助识别。在窄侧边栏中，纯文字 Tab 不够直观，且与左侧导航栏的纯图标风格不统一。

**复现**：
1. 进入设置视图
2. 查看顶部 Tab 栏

**根因**：`SettingsView.tsx` 的 `TabButton` 组件只渲染文字。

**影响范围**：设置视图；美观性问题。

## 二、视觉问题（Visual）

### V-01 🟡 整体缺少现代简洁感

**现象**：当前 UI 风格偏"功能堆砌"，缺少现代简洁风（参考 Linear / Notion / ChatGPT 侧边栏）的特征：
- 卡片圆角偏小（`rounded-lg` = 8px），现代风通常 10–12px
- 阴影使用不足或不统一，卡片缺少层次感
- 间距偏紧凑，留白不足
- 颜色对比偏硬，缺少柔和的中间色
- 字体层级不明显，标题和正文区分度不够

**影响范围**：全局视觉风格。

---

### V-02 🟡 消息气泡样式单调

**现象**：
- 用户消息：纯蓝色背景 `bg-primary`，白色文字，无阴影
- Assistant 消息：灰色背景 `bg-surface-2`，深色文字
- 两种气泡样式对比强烈但缺少细节（如头像、发送时间、hover 操作）

**影响范围**：对话视图消息列表。
