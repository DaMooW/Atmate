# UI 布局与视觉改版 — Requirements

> 评审定案（2026-09-15，AskUserQuestion 三组确认）：
> - **范围**：布局+视觉（修复 issues.md 中 L-01 至 L-08、V-01、V-02 共 10 项；交互问题 I-01 至 I-06 留待后续迭代）
> - **设计方向**：现代简洁风（参考 Linear / Notion / ChatGPT 侧边栏，统一背景、柔和阴影、圆角卡片、留白充足）
> - **会话列表模式**：抽屉覆盖层（从左侧滑出，覆盖在对话视图上方，不挤压主内容区，带半透明遮罩，点击外部关闭）
>
> 依据：[mission.md](../../mission.md)、[roadmap.md](../../roadmap.md)、[techniqueStack.md](../../techniqueStack.md)、[issues.md](./issues.md)

## 1. 背景（Why）

M1 已于 2026-09-14 交付（roadmap §3，T1.1–T1.10 全绿，273 测试通过），核心功能（对话 / 流式 / API配置 / 角色 / token / 会话管理）全部可用。

但用户实际试用后发现**布局和视觉存在明显问题**，影响产品的第一印象和日常使用体验。详细问题清单见 [issues.md](./issues.md)，其中两个严重问题（L-01 会话列表挤压主内容区、L-02 角色名称竖排）直接影响核心可用性。

本次改版是 **M1 交付后的体验优化迭代**，不新增功能、不改变数据模型、不改变核心逻辑，专注于：
1. 修复布局 bug（确保在 Chrome 侧边栏典型宽度 320–400px 下所有视图可用）
2. 提升视觉品质（现代简洁风，统一配色、圆角、阴影、间距）
3. 改进信息层级（空状态引导、状态条信息密度、Tab 可识别性）

引用的 FR/NFR：
- NFR-1（性能：UI 不阻塞，打开到可输入 <300ms）——改版不得降低性能
- NFR-5（可维护性：分层架构，TS strict）——改版保持现有分层
- 不新增 FR，所有改动属于现有 FR 的 UI 实现层优化

## 3. 决策（Decisions）

| # | 决策 | 依据 |
|---|---|---|
| D-UI.1 | 会话列表采用**抽屉覆盖层**（overlay drawer）模式，而非窄边栏并排或全屏切换 | 评审 Q3：用户选择抽屉覆盖层。理由：(1) 不挤压主内容区，320px 下对话视图始终完整可见；(2) 符合 ChatGPT / Notion 等现代侧边栏应用的交互范式；(3) 实现成本适中，用 CSS transform + transition 即可 |
| D-UI.2 | 整体视觉风格定为**现代简洁风**，参考 Linear / Notion / ChatGPT 侧边栏 | 评审 Q2：用户选择现代简洁风。关键特征：统一背景色（导航栏与主内容区同色系或微差异）、柔和阴影、10–12px 圆角、充足留白、清晰字体层级 |
| D-UI.3 | 本次范围严格限定为**布局+视觉**，不触碰交互逻辑 | 评审 Q1：用户选择"布局+视觉"。交互问题（I-01 至 I-06）记录在 issues.md 但不修复，避免范围蔓延 |
| D-UI.4 | 改版保持**现有组件层级和分层架构**（App / Sidebar / ChatView / SettingsView / SessionList 等），不做架构重构 | techniqueStack §4 组件层级约定；本次是 UI 实现层优化，不是架构重构 |
| D-UI.5 | 颜色 token 体系在 `style.css` 中调整，组件继续使用语义色名（`bg-surface` / `text-text` / `border-border` 等），不直书颜色值 | techniqueStack §1 选型 #5 语义 token 约定；M0 已确立此模式，本次调整 token 值而非组件类名 |
| D-UI.6 | 抽屉动画使用 CSS `transform: translateX()` + `transition`，不引入 framer-motion 等动画库 | 保持依赖最小化（package.json 当前无动画库）；简单滑入动画 CSS 足够 |
| D-UI.7 | 角色列表卡片布局改为**垂直信息层级**：角色名称（单行不换行）+ 描述 + 系统提示词预览，操作按钮移至卡片底部或右上角固定区域 | L-02 根因分析：当前水平布局在窄宽度下名称区被挤压；垂直布局更适合侧边栏窄容器 |
| D-UI.8 | 空状态引导根据 `apiConfigs.length === 0` 动态判断：未配置时显示"去配置 API"按钮（点击跳转到设置视图），已配置时显示原通用提示 | L-06：首次使用用户需要明确引导；`ChatView` 已有 `activeConfig` 变量可复用 |
| D-UI.9 | 不改变 manifest 权限、不新增依赖、不改变构建配置 | 本次是纯 UI 改版，无权限/依赖/构建需求 |

## 4. 上下文与约束（Context & Constraints）

### 4.1 交互稿要点

**会话列表抽屉（T-UI.1）**：
- 触发：点击左侧导航栏顶部的会话列表图标
- 展示：从左侧滑入，宽度 260px（比原 240px 略宽，优化内容展示），覆盖在主内容区上方
- 遮罩：主内容区上方覆盖半透明黑色遮罩（`bg-black/30`），点击遮罩关闭抽屉
- 动画：`transform: translateX(-100%)` → `translateX(0)`，duration 200ms，ease-out
- 关闭：点击遮罩、点击会话项、点击关闭按钮（×）、按 Escape 键
- 选中会话后自动关闭抽屉

**角色列表卡片（T-UI.2）**：
- 垂直布局：顶部行（角色名称 + 默认标签 + 操作按钮），下方描述，再下方系统提示词预览（2 行截断）
- 角色名称 `whitespace-nowrap overflow-hidden text-ellipsis`，不换行
- 操作按钮（复制/编辑/删除）始终可见（不只是 hover），使用图标按钮
- 卡片圆角 10px，边框 1px，hover 时微阴影

**全局视觉（T-UI.3, T-UI.9）**：
- 浅色模式：导航栏 `bg-surface`（白色），主内容区 `bg-bg`（#f6f6f4），通过微色差区分层级而非强对比
- 深色模式：导航栏 `bg-surface`（#15191e），主内容区 `bg-bg`（#101418），同理
- 卡片统一 `rounded-xl`（12px）或 `rounded-lg`（8px）按层级区分
- 阴影：卡片 hover 时 `shadow-sm`，模态/抽屉 `shadow-lg`
- 间距：p-4（16px）为基础单位，重要区域 p-5（20px）

### 4.2 数据与接口变更

- **无 storage schema 变更**：不改变 `AppStorageState`、`Session`、`Role`、`ApiConfig` 等类型
- **无 core 逻辑变更**：不改变 `tokens.ts`、`session.ts`、`systemPrompt.ts` 等核心模块
- **无 infra 变更**：不改变 LLM 客户端、storage 同步层
- **组件 props 可能微调**：如 `SessionList` 可能新增 `onClose` 之外的 props（如 `isOpen`），但不改变数据流向

### 4.3 边界与异常

- **抽屉在极窄宽度（<300px）**：抽屉宽度 260px，在 300px 容器中仍有 40px 遮罩可见；如果容器 <280px，抽屉宽度应自适应为 `min(260px, 85vw)`
- **深色模式下的遮罩**：`bg-black/30` 在深色模式下可能不够明显，可考虑 `bg-black/50`
- **动画性能**：使用 `transform` 而非 `width` 动画，确保 GPU 加速，不影响 NFR-1 性能要求
- **无障碍**：抽屉打开时焦点管理（focus trap）为加分项，不强制；Escape 键关闭为必须
- **会话列表为空时**：抽屉仍可打开，显示空状态引导

### 4.4 技术约束

- Tailwind v4（`@tailwindcss/vite`），使用 `@theme inline` 语义 token
- React 18 + TypeScript strict
- WXT 0.21 构建，产物输出到 `dist/chrome-mv3`
- 现有测试 273 例必须全绿，不得因 UI 改版破坏现有测试
- 组件代码风格保持一致：函数组件、`interface Props`、JSDoc 注释

## 5. 成功标准（Success Criteria）

1. **布局可用性**：在 320px / 360px / 400px / 500px 四种宽度下，所有视图（对话 / 设置·三个Tab / 会话列表抽屉 / API配置表单）均无内容溢出、无文字截断、无元素重叠
2. **严重问题修复**：L-01（会话列表挤压）和 L-02（角色名称竖排）完全修复
3. **视觉一致性**：浅色/深色双模式下，导航栏与主内容区颜色协调，无明显割裂感
4. **现代简洁风**：整体视觉达到"参考 Linear / Notion / ChatGPT 侧边栏"的基本水准（圆角、阴影、留白、字体层级统一）
5. **零回归**：`pnpm test` 全绿（273+ 例），`pnpm typecheck` 通过，`pnpm lint` 通过，`pnpm build` 成功
6. **性能不降级**：侧边栏打开到可输入时间仍 <300ms（NFR-1），抽屉动画流畅无卡顿
