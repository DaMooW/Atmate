# Spec 模板（roadmap §1 spec-first）

> 使用：为每个里程碑建目录 `specs/<YYYYMMDD>-<slug>/`（自 M0 起取代单文件 spec），分支与目录同名。评审通过才动代码；实现中发现偏差，**改 spec 再改码**。
> 首例：[20260913-m0-init/](20260913-m0-init/)。

目录内固定三件：

## 1. `requirements.md` —— 背景、范围、决策、上下文

承载六段骨架的前五段（背景 → 范围 → 交互稿 → 数据与接口变更 → 边界与异常），其中：

- **背景**：为什么做这个里程碑/特性——痛点、引用的 FR/NFR、前置里程碑；
- **范围**：在/不在本次范围；引用 [mission.md](../mission.md) FR/NFR 编号与 [roadmap.md](../roadmap.md) 任务号 T*.x；
- **决策**：编号表格（决策 / 依据），评审结论逐条落表；
- **上下文与约束**：交互稿要点、数据与接口变更（storage schema、消息表、组件层级；引用 [techniqueStack.md](../techniqueStack.md) §5/§6）、边界与异常（失败降级、竞态、超长/超限、权限缺失）。

## 2. `plan.md` —— 编号任务组

拆除可执行的任务组（1、2、3…），与 roadmap 的 T*.x 一一对应：每组写明**目标**、可勾选子任务、完成判据。完成一项勾一项，并回勾 roadmap.md。

## 3. `validation.md` —— 验收与合并判据

- 自动化门禁（命令 / 预期 / 实际结果，含日期）；
- 人工验收清单（可复现步骤，供验收人走查）；
- 合并清单（Definition of Merged）：合回 `main` 的前置条件与分支处理方式。
