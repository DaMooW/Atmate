> 分支：`20260914-m1-fix-storage-echo` · 上游：[roadmap.md §3](../../roadmap.md) M1、[M1 spec](../20260914-m1-sidepanel-chat/)
> 类型：验收期发现的实现缺陷（实现与 spec 不符 → 先改 spec 再改码，roadmap §1）
> 触发：2026-09-14 M1 人工验收（真实 DeepSeek 端点）
> 状态：已实现（2026-09-14，真机复验通过；见 [validation.md](validation.md)）

## 1. 背景

M1 验收第 2 条要求"流式输出首块可见；表格/代码块渲染正确；停止生成立即生效"。实测：
服务端 SSE 完整输出 793 字正文（含代码块围栏、`finish_reason: stop`），应用只落库 550 字，
中间缺整段内容、结尾被截断，代码块因此没有渲染成 `<pre>`。

证据（2026-09-14，Chrome 152 + 真实 DeepSeek 端点 `deepseek-chat`）：

| # | 实验 | 结果 |
|---|---|---|
| 1 | 抓包比对服务端流与应用落库 | 服务端 793 字 / 落库 550 字，中间缺块 |
| 2 | 同一段 SSE 离线重放（16KB / 1KB / 64B / 1–300B 随机切块） | 五种切法都精确还原 793 字 → **SSE 解析器无问题** |
| 3 | 页面探针：200 次快速 `storage.local.set` | 200 个 onChanged 事件里 **199 个是过期回声**（事件到达时存储中已是更新的值） |
| 4 | 流式期间监听 `at:sessions` 变更 | 589 次变更中 3 次长度倒退，最大一次 824 → 193 字；最终落库仅 212 字 |

根因：[store.ts](../../infra/storage/store.ts) 的 onChanged 监听把**本上下文自己写入产生的回声**
当成外部变更，仅做引用比较（`current.sessions !== newValue`）就无条件套用。`storage.local.set`
是异步的，回声到达时存储里往往已是更晚的值；把旧快照写回内存后，后续流式增量叠加在旧内容上，
中间那段便永久丢失——渲染与落库同时可见，关闭重开后仍是缺的。

## 2. 范围

**在范围内**（属 roadmap M1 T1.1「storage 同步层」，不新增任务号）：

- 忽略本上下文写入产生的回声；其他上下文的变更仍照常回流（ADR-006 原则不变）
- 补 L2 测试：滞后 / 乱序回声不导致状态倒退，外部变更仍回流
- 文档同步：techniqueStack §5 与 §12、decisionLog、roadmap §10、M1 validation §2.2

**不在范围内**（另立里程碑或后续条目）：

- 流式期间写盘节流（每轮数百次整数组写入的性能问题）→ 记入 M5 候选
- 数据结构变更（schema 仍为 v1；不加版本号字段）
- 多上下文写入冲突的通用解决（版本向量 / CRDT）——M1 是单写入方，不做
- 已丢失的历史消息回填（本地演示数据，重发即可）

## 3. 决策

| # | 决策 | 依据 |
|---|---|---|
| F1 | 写入时登记本次写入的**指纹 FIFO**；onChanged 命中即忽略，未命中才算外部变更 | 回声与本地写入一一对应，指纹可容忍外部写入混入；无需 schema 变更 |
| F2 | 指纹 = `JSON.stringify` + FNV-1a 32 位（附长度），FIFO 上限 512 | 内存恒定、比较成本低；实测单次响应内写入 589 次，上限足以覆盖回声积压 |
| F3 | 不采用"时间窗内一律忽略回声" | 会吞掉其他上下文的真实变更，且依赖魔法时长 |
| F4 | 不采用"给 storage 载荷加版本号" | 需改 schema v1，代价大于收益 |
| F5 | 不回溯修复已丢字的历史会话 | 本地演示数据，重发即可；避免一次性修复脚本 |

## 4. 上下文与约束

- 相关：tech §5（同步层）、ADR-006（storage 唯一真相源）、ADR-009（L2 用 `fakeBrowser` + `vi.mock`）
- 边界与异常：
  - 外部写入的值恰好等于本地写过（指纹命中）→ 忽略也无害，内存中已是该值
  - 回声乱序到达 → 按成员匹配，不依赖顺序
  - FIFO 溢出（持续写入、回声迟迟不到）→ 丢弃最旧指纹；该次回声退回旧行为（被当外部变更套用），不引入新风险
  - 键被删除（`newValue === undefined`）→ 维持既有行为，不回流
- 兼容性：不改 storage schema、不改权限、不改 `useStorageStore` 对外形状（仅内部行为变化）
