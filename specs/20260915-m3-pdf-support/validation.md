## 2. 人工验收清单（可复现）

### 2.1 PDF 接管与选择弹窗（T3.2，核心验收）

**场景 A：默认询问（首次）**
- [ ] 确保 `pdfOpenMode === 'ask'`（设置页确认或重置）
- [ ] 在浏览器打开一个在线 PDF 链接（如 `https://example.com/test.pdf`）
- [ ] 页面加载前弹出选择窗：标题"打开 PDF"、两个按钮"在扩展查看页打开" / "继续用 Chrome 原生查看器"、"记住选择"复选框
- [ ] 点击"在扩展查看页打开"（不勾选记住）→ 跳转到 `viewer.html?file=...`，PDF 正常渲染
- [ ] 再打开另一个 PDF → 仍弹出选择窗（未记住）

**场景 B：记住选择**
- [ ] 打开 PDF → 勾选"记住选择"→ 点击"在扩展查看页打开"
- [ ] 再打开 PDF → 直接跳转到 viewer 页，**不弹窗**
- [ ] 设置页确认"PDF 打开方式"显示为"始终用扩展查看页"
- [ ] 设置页切换为"每次询问"→ 再打开 PDF → 恢复弹窗

**场景 C：始终原生**
- [ ] 设置页切换为"始终用 Chrome 原生"
- [ ] 打开 PDF → Chrome 原生查看器打开，**不跳转、不弹窗**
- [ ] 设置页切回"每次询问"→ 恢复弹窗

**场景 D：非 PDF 链接不受影响**
- [ ] 打开普通网页（`.html` / 无扩展名）→ 正常加载，无弹窗无跳转
- [ ] 打开图片（`.png` / `.jpg`）→ 正常显示，无弹窗

### 2.2 viewer 页渲染与工具栏（T3.1）

- [ ] viewer 页打开后，PDF 第一页渲染清晰，文字可选中（textLayer 生效）
- [ ] 工具栏显示：页码"第 1 / 总 N 页"、上一页/下一页按钮、缩放 +/-/适应宽度、下载、"在原生查看器打开"
- [ ] 点击下一页 → 页码更新，新页渲染；点击上一页 → 返回
- [ ] 缩放 + / - → 页面大小变化；适应宽度 → 页面填满视口宽度
- [ ] 点击"在原生查看器打开"→ 新标签页用 Chrome 原生打开同一 PDF
- [ ] 点击下载 → 下载原 PDF 文件

**file:// 本地 PDF（T3.1, D3）**：
- [ ] 未开启"允许访问文件网址"时，打开 `file:///path/to/test.pdf` → viewer 显示引导页（说明 + 打开 chrome://extensions 按钮）
- [ ] 在 chrome://extensions 开启"允许访问文件网址"后，点击"已开启，重试"→ PDF 正常渲染
- [ ] 已开启权限时，直接打开本地 PDF → 正常渲染，无引导页

**加载失败（T3.1, D13）**：
- [ ] 打开一个损坏的 PDF 文件 → 显示"文件损坏"错误 + "在原生查看器打开"按钮 + 重试
- [ ] 打开一个密码保护的 PDF → 显示密码输入框；输入正确密码 → 渲染；输入错误 → 提示密码错误

**扫描件检测与提示（T3.1, D16/D17，核心验收）**：
- [ ] 打开扫描版 PDF（无文字层）→ viewer 渲染完成后，顶部出现**黄色警告条**："⚠️ 此页可能是扫描件（无文字层），划词可能无法选中文字。M4 上线后可使用「附当前页为图片」发送给 AI。"
- [ ] 警告条可手动关闭（× 按钮），关闭后本次会话不再出现
- [ ] 翻到有文字层的页面 → 警告条自动隐藏
- [ ] 再翻回无文字层页面 → 警告条重新出现
- [ ] 连续 5 页均无文字层 → 警告条文案升级为"⚠️ 此文档为扫描件（无文字层）"，常驻显示
- [ ] 打开正常文字版 PDF → **不出现**警告条
- [ ] 混合 PDF（部分页有文字、部分页扫描）→ 逐页检测，有文字层的页无警告、扫描页有警告
- [ ] 在扫描页划词 → 浮动按钮可出现（如果有可选中的像素层文字），但素材卡片显示红色小字"此页无文字层，选中内容可能无效"
- [ ] 在扫描页划词且选区为空 → 侧边栏提示"未能从扫描件中提取文字，建议使用「附当前页为图片」（M4）"
- [ ] 扫描件切换到"附 PDF 全文"档 → 显示"此 PDF 无文字层，无法提取全文。建议使用「附当前页为图片」（M4）"，不发送空内容

- [ ] token 预览显示全文估算 token 数

**>50 页 PDF**：
- [ ] 切换到"附 PDF 全文"→ 预览区显示截取的 11 页内容（当前页 ±5）
- [ ] 显示截断标注："全文共 X 页，已截取第 Y-Z 页"

- [ ] 在最后一页划词 → 截取范围为最后 6 页（clamp，不超出总页数）

## 3. 已知问题（Known Issues）

### 3.1 PDF viewer 内划词文本偏移（未解决，延后处理）

**现象**：在自建 viewer 页内划词时，素材卡片显示的文本与用户实际选中的文本存在偏差（通常是向前多取了几个字符）。

**根因分析**：
- pdf.js TextLayer 将 PDF 文本拆分为多个绝对定位的 `<span>` 元素，每个 span 对应一个文本块
- 浏览器原生选区（Selection/Range）在跨绝对定位 span 时，其 `toString()` 和文本节点遍历的拼接顺序与视觉阅读顺序可能不一致
- 已尝试修复：`core/selection/extract.ts` 用 Range 精确遍历文本节点 + 过滤零宽字符，但未解决根本问题（span 顺序/偏移）
- M2 网页划词不存在此问题，因为网页文本在正常流 DOM 中，选区行为符合预期

**影响范围**：
- 仅影响 viewer 页内划词的文本准确性
- 不影响 PDF 渲染、翻页、缩放、扫描件检测、附全文功能
- 不影响 M2 普通网页划词

**当前状态**：用户确认暂不深入解决，记录为已知问题。后续可考虑的方向：
1. 基于 pdf.js textContent 的坐标数据重建选区文本（不依赖浏览器原生 Selection）
2. 升级 pdf.js 版本或使用其官方 viewer 的选区处理逻辑
3. 接受一定误差，在 UI 上标注"PDF 划词可能存在偏差"

**关联任务**：T3.3（viewer 内划词）
