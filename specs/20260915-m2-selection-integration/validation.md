## 2. 人工验收清单（可复现）

### 2.1 划词分流（D16，核心验收）

**场景 A：侧边栏已打开 → 零点击直接填入**
- [ ] 打开侧边栏（保持打开状态），在网页上划词 → 200ms 后侧边栏内出现素材卡片（从下往上滑入）
- [ ] **不显示浮动按钮**（网页上无任何按钮出现）
- [ ] 连续划词多次 → 每次都创建新的素材卡片（多卡片积累）
- [ ] 素材卡片来源标记为 `auto-fill`（与浮动按钮/右键菜单可区分）

**场景 B：侧边栏未打开 → 浮动按钮 + 一次点击**
- [ ] 关闭侧边栏，在网页上划词 → 200ms 后选区右下角出现浮动按钮
- [ ] 按钮为 32×32 圆形 Atmate 图标，深色半透明背景
- [ ] hover 按钮显示 tooltip "发送到在伴"，背景变亮
- [ ] 点击按钮后 < 300ms 面板前置且素材卡片就位
- [ ] 点击后浮动按钮立即消失（即时反馈）
- [ ] 素材卡片来源标记为 `float-button`

**5 站点兼容性**（两种场景均需验证）：
- [ ] GitHub（代码托管页，深色主题可选）
- [ ] 一个带 Dark 主题的站点（如某个人博客）
- [ ] MDN 文档页（长文、多段落）
- [ ] 一个富文本内容站（非 Google Docs，如知乎/掘金）
- [ ] 一个极简风格站（如 example.com 或纯文本页）

**按钮定位与防溢出**：
- [ ] 按钮出现在选区右下角，不受站点 CSS 影响（Shadow DOM 隔离）
- [ ] 页面滚动时按钮跟随选区重新定位
- [ ] 选区在视口右边缘时，按钮不溢出视口（左移）
- [ ] 选区在视口下边缘时，按钮显示在选区上方（上移）

### 2.2 右键菜单（roadmap 验收第 1 条补充）

- [ ] 选中文字后右键，菜单中出现"发送选中内容到在伴 AI 侧边栏"
- [ ] 点击右键菜单项后 < 300ms 面板前置且素材卡片就位
- [ ] 素材卡片来源标记为右键菜单（与浮动按钮来源可区分）
- [ ] 未选中文字时右键，菜单项不出现（Chrome 原生行为）

### 2.3 素材卡片交互（roadmap 验收第 2、3 条）

- [ ] 素材卡片显示来源角标（网页标题），hover 显示完整 URL
- [ ] 原文编辑区显示选区文本，可编辑
- [ ] 补充说明输入框可输入，placeholder 为"补充说明，如：术语按前端领域"
- [ ] 编辑原文/补充说明后，采用时 Composer 中内容反映编辑结果（日志核对请求体）
- [ ] 上下文档位切换：仅选区 / ±相邻段落 / 整页正文，默认选中 ±相邻段落
- [ ] 切换档位后上下文预览区域内容更新
- [ ] token 预览随档位切换和原文编辑实时更新（"≈xxx token"）
- [ ] 采用按钮：点击后卡片消失，内容填入 Composer 输入框
- [ ] 丢弃按钮：点击后卡片消失，不填入 Composer
- [ ] 卡片顶部常显"将发送至：<当前会话名>"
- [ ] 点击"转新会话"后变为"将发送至：新会话"，采用时创建新会话
- [ ] 无激活会话时，落点直接显示"将发送至：新会话"

### 2.4 输入框/地址栏不误触发（roadmap 验收第 4 条）

- [ ] 在 `<input>` 输入框内划词，不显示浮动按钮
- [ ] 在 `<textarea>` 内划词，不显示浮动按钮
- [ ] 在 `[contenteditable="true"]` 元素内划词，不显示浮动按钮
- [ ] 在地址栏划词，不显示浮动按钮（Chrome 原生行为）
- [ ] 空选区（点击不拖动）不显示浮动按钮
- [ ] 纯空白选区（只选中空格/换行）不显示浮动按钮

### 2.5 上下文供给三档（roadmap 验收第 5 条）

- [ ] **仅选区档**：素材卡片预览只含【用户选中的内容】，采用后请求体只含选区文本
- [ ] **±相邻段落档（默认）**：预览含【用户选中的内容】+【附带的上下文·前一段落】+【附带的上下文·后一段落】；采用后请求体含完整三区块
- [ ] **整页正文档**：预览含【用户选中的内容】+【附带的上下文·整页正文】；readability 提取成功
- [ ] **整页提取失败降级**：在 readability 无法提取的页面（如纯 JS 渲染、无正文结构）切换到整页档，卡片显示红色警告"整页提取失败，已降级为仅选区"，实际发送内容为仅选区
- [ ] **prompt 标记正确**：抓包确认请求体中【用户选中的内容】与【附带的上下文】有明确分界标记，AI 可区分
- [ ] **token 预览与实发一致**：卡片上显示的 ≈token 数与实际请求体估算值一致（含标记文字）

### 2.6 消息链路容错与分流（T2.5, D16）

- [ ] **冷启动竞态**：关闭侧边栏 → 在网页划词点击浮动按钮 → 面板打开后素材卡片出现（不丢失）
- [ ] **侧边栏已打开时划词**：零点击直接填入素材卡片，不显示浮动按钮（D16 场景 A）
- [ ] **侧边栏未打开时划词**：显示浮动按钮，点击后打开侧边栏并填入（D16 场景 B）
- [ ] **panelOpen 状态准确性**：打开侧边栏后划词直接填入；关闭侧边栏后划词显示浮动按钮；状态切换无延迟（port 连接/断开即时触发）
- [ ] **同 Tab 重复发送（侧边栏已打开）**：连续划词发送两次，出现两张独立素材卡片
- [ ] **同 Tab 重复发送（侧边栏未打开）**：连续划词两次，浮动按钮暂存最新选区（覆盖旧暂存），点击后只创建一张卡片（最新选区）
- [ ] **跨 Tab 发送**：在 Tab A 划词发送 → 切换到 Tab B 划词发送 → 两张卡片携带来源 URL 可区分
- [ ] **超长选区**：选中超长文本（>5000 字），不截断；token 超限时 TokenStatusBar 红条禁发
- [ ] **面板已打开时发送**：侧边栏已打开状态下划词点击，素材卡片立即出现（无需等待）
- [ ] **浮动按钮显示后点击页面其他地方**：浮动按钮保持显示；取消选区（点击空白处）后按钮消失

### 2.7 多卡片积累与采用顺序

- [ ] 连续划词发送 3 次，出现 3 张卡片，按时间顺序排列
- [ ] 按任意顺序采用卡片，Composer 中内容按采用顺序追加（空行分隔）
- [ ] 采用部分卡片后，剩余卡片仍可操作
- [ ] 丢弃中间一张卡片后，其余卡片位置正常

## 4. 复现步骤（验收人按此走查）

1. `git checkout 20260915-m2-selection-integration && pnpm install && pnpm build`
2. Chrome → `chrome://extensions` → 开发者模式 → 加载已解压的扩展程序 → 选 `dist/chrome-mv3`
3. **场景 A（侧边栏已打开）**：点击工具栏图标打开侧边栏 → 打开任意网页（如 MDN 文档）→ 选中一段文字 → 观察 200ms 后侧边栏内出现素材卡片（网页上无浮动按钮）→ 连续划词多次观察多卡片积累
4. **场景 B（侧边栏未打开）**：关闭侧边栏 → 在网页上选中一段文字 → 观察 200ms 后选区右下角出现浮动按钮 → hover 观察 tooltip → 点击按钮 → 观察侧边栏打开并填入素材卡片
5. 选中文字后右键 → 点击"发送选中内容到在伴 AI 侧边栏" → 观察分流行为（已打开则直接填入，未打开则打开并填入）
6. 在素材卡片中编辑原文、输入补充说明、切换上下文档位 → 观察预览和 token → 点击采用 → 观察 Composer → 发送 → 抓包确认请求体含【用户选中的内容】/【附带的上下文】标记
7. 在输入框/textarea 内划词 → 确认不显示浮动按钮、不自动填入
8. 关闭侧边栏 → 划词出现浮动按钮 → 不点击按钮，重新划词 → 观察浮动按钮重新定位、暂存被覆盖 → 点击按钮确认填入的是最新选区
9. 在 readability 难以提取的页面切换整页档 → 观察降级警告
10. 跑 `pnpm typecheck && pnpm lint && pnpm test` 确认门禁全绿
11. 回归 M1 功能：手动输入对话、会话管理、设置页
